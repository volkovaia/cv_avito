# Классификация ориентации текстового кропа (0° / 180°)

Модель для промежуточного этапа OCR-пайплайна: определяет, повёрнут ли найденный детектором текста бокс на 180° (вверх ногами), и выдаёт калиброванную вероятность p_180.

## Результат

**1 − Brier Score = 0.773** (Brier = 0.227) на тестовой выборке из 20 000 боксов.

## Подход

Обучающих данных с разметкой не предоставлялось, поэтому решение построено на синтетически сгенерированных данных: кастомный генератор на PIL/OpenCV рендерит текст
(русские или английские слова, цены, случайные символы) в правильной ориентации с широким набором аугментаций, имитирующих реальные фото - разные шрифты, цветные или металлик-фоны, тиснение, водяные знаки, перспектива, motion blur, JPEG-артефакты, пикселизация от даунскейла. Метка 0/180 создаётся автоматически случайным переворотом на этапе загрузки батча.

Модель: (ImageNet-претрейн) компактная архитектура, около 1,5 млн параметров

Валидация без разметки теста: поскольку размечать тест запрещено условием, а обычная hold-out валидация на синтетике не отражает реальный домен, использовалась self-consistency проверка, то есть для случайных тестовых кропов без меток сравнивались вероятности оригинала и его же версии, повёрнутой на 180° (p1 + p2 должно быть ≈ 1 у корректной модели). Эта метрика служила ориентиром при итеративном улучшении генератора синтетики.

Калибровка: Platt scaling + пост-хок линейное сжатие вероятностей к 0.5, компенсирующее переуверенность модели на реальном домене (коэффициент выведен аналитически из фактического результата первой отправки, без использования меток отдельных примеров).

## Что не вошло в решение

Реальные open-source датасеты (ICDAR-MLT - не содержит кириллицы; MIDV-500 - недоступен из-за сетевых ограничений окружения) и mixup-аугментация (не дала улучшения по self-consistency проверке). Подробности и обоснование в текстовом описании внутри ноутбука.
